📖 Guide

How each scenario works

Every scenario calls the Ninja sandbox only — never production. Every form field already has a working value from Ninja's documented test fixtures, so you can submit any form as-is. Two scenarios need one extra step first (see the callout below) — everything else works the moment the server is running.

⚠ Two scenarios need a public webhook URL

Vendor Onboarding and the Agent Network's aggregator registration create hosted KYB/KYC flows — Ninja emails your business/director a link, they fill it out on Ninja's own page, and Ninja calls your server back on completion. Ninja validates that webhook_url is a real public address before it will even create the flow — http://localhost:4000 is rejected outright. Point a tunnel (ngrok, cloudflared) or a real deployment at this server, set PUBLIC_URL in .env to that address, and restart. Every other scenario below is a direct server-to-sandbox call with no callback involved, so it needs none of this.

🏢 Vendor Onboarding needs PUBLIC_URL

What it's for: a marketplace vendor can't get paid until their business and every director clear verification — stops payments to shell companies and ghost suppliers.

Flow: Apply (business name, RC number, contact, director ID type) → server pulls the CAC record (company/lookup) and directors/shareholders (company/advanced-lookup) → bulk-identifies every director in one call → sends the business a hosted KYB link and each director a hosted KYC link → Ninja calls back on completion → once the business and every director pass, a payout wallet activates.

Try it: the form is pre-filled with RC 0000000 (resolves to "Ninja Demo Company Limited"). Submit as-is.

🎰 Gaming & Betting works immediately

What it's for: age/identity verification at signup, and a re-check before every payout — stops bonus-farming (one person, many accounts).

Flow: Signup form → server calls identify (verify mode) directly → under-18 or no-match is blocked, everyone else activates. A duplicate signup with the same ID is blocked outright (one identity, one account). From the dashboard, "Payout re-check" re-runs the same verify call before releasing funds.

Try it: pre-filled with James Bond / 77777777777 (passes). Use the "Not found" chip to see a block.

💳 Fintechs works immediately

What it's for: per-field name-matching instead of a blunt pass/fail — "Chukwuemeka" vs "Chukwuemeka Emeka" is the same person, not a rejected application.

Flow: Onboard form → server calls identify (verify mode) → the response's per-field score/recommendation is stored and shown. "Re-run KYC" from the dashboard re-verifies a flagged or high-value account later.

Try it: pre-filled with an exact match. The "Spelling variant" chip reuses the same sandbox ID with a slightly different name to show a partial score.

🌍 International Companies works immediately

What it's for: onboarding Nigerian customers from anywhere, no local entity required — a raw API console for teams integrating directly.

Flow: single (identify, lookup or verify) or bulk (bulk-identify, up to 25 IDs) — every call server-side, every result logged to a visible audit trail (timestamp, request ID, operator).

Try it: every field is pre-filled; the bulk chip queues one ID per documented outcome (found, AML match, not found, simulated failure).

🛰️ Agent Network KYC recruit works immediately · aggregator needs PUBLIC_URL

What it's for: field recruitment of payment agents, and catching "one BVN behind fifty terminals" — an identity already tied to another terminal, the classic agent-network fraud pattern.

Flow: Recruit form → server calls identify (verify mode) on the spot → a duplicate identity across terminals is flagged (not silently blocked) for review. Separately, aggregator businesses go through the same hosted-KYB pattern as Vendor Onboarding.

Try it: recruit James Bond twice with different terminal IDs to see the duplicate flag fire.

🪪 Employee Verification dashboard lookup works immediately · hosted link needs PUBLIC_URL

What it's for: confirming the person who resumes Monday is the person you interviewed.

Flow: "Dashboard lookup" calls identify (verify mode) server-side and clears instantly. "Hosted link" instead sends the candidate a selfie + liveness link — for remote candidates the simple lookup can't cover.

Try it: dashboard lookup is pre-filled and works right away; switch the check method to see the hosted-link path.
